# Orchestrated Mode — Multi-Terminal Agent Team on a Self-Generated Task Board

Loaded when the `/new-project` interview picks `orchestrated` (Q10). The scaffold
generates a **per-project MCP task board** plus role commands/agents so several
Claude Code terminals coordinate through shared, deterministic state — no
databases, no daemons, no websockets. File-based state + stdio MCP only.

---

## 1. What this mode is (and when to pick it)

A team of terminals over one task board:

- **Terminal 1 — Orchestrator** (`/orchestrate`): owns the board via MCP tools,
  plans with a subagent, reviews handoffs, closes tasks. **Never writes code.**
- **Terminals 2..N — Workers** (`/worker`): each in its own git worktree,
  claiming tasks, implementing inside a declared file scope, submitting handoffs.
- **Sentinel** (subagent): screens every handoff for semantic red flags.
- **Validators**: the existing global `code-reviewer` / `security-reviewer`
  agents, run blind (diff + acceptance criteria only).

Pick it over the alternatives:

| | `multiple-instances` | `orchestrated` | `/mission-control` |
|---|---|---|---|
| Task list | Static, pre-written prompts | **Dynamic board** — create/claim at runtime | Contract + milestone plan |
| Anti-overlap | Prose convention in prompts | **Enforced by the tool** (rejects overlap) | Serial workers (one writer) |
| Workers | Human pastes prompts | Terminals self-serve via `claim_task` | Subagents of one session |
| Best for | 2–3 known, fixed tracks | Evolving work split across live terminals | One session driving a long build |

They are alternatives per work-stream: do not run a mission and a board on the
same goal at once.

## 2. Terminal topology

```
main checkout (terminal 1 — orchestrator, /orchestrate)
│   coordination/board.json      ← single source of truth (gitignored)
│   coordination/handoffs/*.md   ← one per submitted task
│   coordination/DASHBOARD.md    ← regenerated by every tool call
├── ../<repo>-wt/worker-2   (terminal 2 — /worker, own worktree)
└── ../<repo>-wt/worker-3   (terminal 3 — /worker, own worktree)
```

- Every terminal spawns its own `board_server.py` process via the tracked
  `.mcp.json` (`uv run --script coordination/board_server.py`). All processes
  resolve `git rev-parse --git-common-dir` and converge on the **main
  checkout's** `coordination/` — N terminals, one board.
- Worktrees are per **worker seat**, not per task:
  `git worktree add ../<repo>-wt/worker-2 -b work/worker-2-base`. Inside its
  worktree, a worker branches `feat/T-XXX-<slug>` off `main` per claimed task.
- Concurrency is handled by the server (`fcntl` lock + atomic writes). Local
  disk only — do not put the repo on NFS.

## 3. Task lifecycle

| From → To | Tool | Actor |
|---|---|---|
| — → `open` | `create_task` | orchestrator |
| `open` → `claimed` | `claim_task` | worker (sets assignee) |
| `claimed` → `in_progress` | `update_progress` | assignee only |
| `claimed`/`in_progress` → `handoff_submitted` | `submit_handoff` | assignee only |
| `handoff_submitted` → `done` | `close_task(done)` | orchestrator; no open blocker flags |
| `handoff_submitted` → `in_progress` | `close_task(rejected)` | orchestrator (+ auto-flag with reason) |
| any except `done` → `cancelled` | `close_task(cancelled)` | orchestrator |

Anything else is rejected by the server. `update_progress` doubles as the
heartbeat — tasks with no update for `BOARD_STALE_MINUTES` (default 30) get
auto-flagged as stale on the next `get_board`.

## 4. Anti-overlap contract

Every task declares `file_scope`: relative globs it owns (`src/auth/**`,
`tests/test_auth.py`). The server **rejects** `create_task`/`claim_task` when a
scope may intersect any task that isn't `done`/`cancelled`, naming the
colliding task and pattern.

The matcher is conservative (exact match + directory containment + segment
wildcards; character classes treated as full wildcards, no brace expansion).
It over-rejects exotic patterns **by design**: a false positive costs one cheap
re-scope; a false negative costs a merge conflict.

Planner rules: prefer directory-level globs; shared files (schemas, config,
CLAUDE.md) belong to exactly one task or a final integration task; use
`depends_on` instead of overlapping.

## 5. Red-flag taxonomy

**Mechanical — enforced by the board server itself:**

| # | Check | Behavior |
|---|---|---|
| M1 | file_scope intersects an active task's scope | REJECT, names offender |
| M2 | Invalid status transition | REJECT |
| M3 | Actor ≠ assignee on progress/handoff | REJECT |
| M4 | Handoff commands missing integer exit codes, or `completed` with nonzero exits / non-empty `left_undone` | REJECT |
| M5 | `files_touched` outside declared `file_scope` | REJECT — worker must `raise_flag` and wait |
| M6 | Stale task (no heartbeat past threshold) | auto-flag `warning` |
| M7 | Worker claims a second task while one is active | REJECT |
| M8 | Task without acceptance criteria / empty scope / absolute or `..` paths | REJECT |
| M9 | `close_task(done)` with open blocker flags; corrupt board on load | REJECT / refuse writes, point at `.bak` |

**Semantic — the `sentinel` agent, invoked by the orchestrator at each handoff:**

| # | Check | Severity |
|---|---|---|
| S1 | Scope creep in the actual git diff (undeclared edits M5 can't see) | blocker |
| S2 | Secrets/credentials in the diff | blocker |
| S3 | Claimed-but-not-verified: criterion asserted without command+exit-code evidence; tests deleted/weakened | blocker |
| S4 | Suspicious code: disabled auth/validation, dynamic exec, undeclared deps, unknown network hosts | blocker |
| S5 | Handoff prose contradicts the diff | blocker |
| S6 | Deviations changing contract-visible behavior (e.g. swapped library/algorithm) | warning → escalate to human |

Sentinel is read-only and *returns* findings; the **orchestrator** files them
via `raise_flag` (no dependency on subagents inheriting MCP tools). Code
quality and deep security review are NOT sentinel's job — after sentinel
passes, the orchestrator runs the global `code-reviewer` and
`security-reviewer` on the blind diff.

## 6. Handoff flow

1. Worker finishes → `submit_handoff` (server validates M4/M5, writes
   `coordination/handoffs/T-XXX.md` in the mission-control schema: Completed /
   Left undone / Commands run with exit codes / Issues discovered / Deviations /
   Files touched / Acceptance criteria).
2. Orchestrator sees `handoff_submitted` → reads the handoff → spawns
   `sentinel` (task id + branch) → files any findings via `raise_flag`.
3. Blocker flags → `close_task(rejected)`; task returns to `in_progress` and
   the worker sees the flag on its next `get_task_status`.
4. Clean or warnings resolved → spawn `code-reviewer` + `security-reviewer`
   with ONLY `git diff main...<branch>` + the acceptance criteria (never worker
   reasoning or the handoff) → `close_task(done)` → human merges the PR.

## 7. Resume story

`board.json` survives restarts. `/orchestrate` with an existing board is a
**RESUME**: read the board, announce status + stale tasks + open flags,
continue — never re-plan from scratch. A dead worker terminal loses nothing:
its task shows stale, and the seat reopens with `/worker <id>` +
`update_progress` on the existing branch. Orchestrator may `close_task
(cancelled)` and re-create a task to reassign truly abandoned work.

## 8. Iron rules (adapted from mission-control)

- **No handoff → task not done.** "The commit message explains it" is not a handoff.
- **Claims without exit codes are not evidence.** The server rejects them; don't massage payloads to pass.
- **One active task per worker.** Enforced.
- **Workers never edit outside their file_scope.** Need a file you don't own? STOP, `raise_flag`, wait for the orchestrator.
- **Only the orchestrator closes tasks.** By convention, not auth — this is a cooperation protocol among your own agents; sentinel + human PR review are the backstop.
- **The orchestrator never writes code.** It plans, dispatches, reviews, closes.
- **Validators stay blind.** Diff + acceptance criteria only.
- **A human merges.** Same PR discipline as everywhere else.

      `.claude/commands/` — fill `{PROJECT_NAME}`, `{PROJECT_SLUG}`

      `.claude/agents/` — fill placeholders

      `board.json.bak`, `handoffs/`, `DASHBOARD.md`, `.board.lock`)
- [ ] Generated CLAUDE.md includes the `## 🎛️ Orchestrated Mode` block from
      `templates/claude-md.md`
