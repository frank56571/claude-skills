# Folder Structure Standard

Every project follows this layout. Adapt sections based on project type.

```
/{project-name}/
├── CLAUDE.md                          # Project instructions (<200 lines)
├── .claude/
│   ├── settings.json                  # Shared config (git tracked)
│   ├── settings.local.json            # Personal config (gitignored)
│   ├── agents/                        # Subagent definitions
│   ├── commands/                      # next.md + verify.md (ALWAYS) + project-specific commands
│   ├── skills/                        # Project-specific skills
│   └── rules/                         # Domain-specific rules
├── config/
│   ├── client-rules/                  # Per-client business rules (JSON)
│   └── category-mappings.json         # Shared mappings
├── prompts/
│   ├── CHANGELOG.md                   # Prompt version history
│   ├── current -> v1/                 # Symlink to active version
│   └── v1/                            # Versioned prompt files
├── src/
│   ├── orchestrator/                  # Orchestration logic (NOT LLM)
│   │   ├── __init__.py
│   │   ├── runner.py                  # Main loop
│   │   ├── router.py                  # Task routing
│   │   └── approvals.py              # Approval gate logic
│   ├── agents/                        # Agent wrappers
│   ├── schemas/                       # Pydantic models (inter-agent contracts)
│   ├── validators/                    # Input/output validation
│   └── connectors/                    # External API clients (QB, Supabase)
├── tests/
│   ├── fixtures/                      # Real anonymized data
│   ├── unit/
│   └── integration/
├── tasks/                             # Repo-local planning (durable lessons go to the vault, not here)
│   ├── todo.md                        # Plan/review tracker (operating system writes here)
│   └── parallel-prompts.md            # Paste-ready per-instance prompts (only if multiple-instances mode)
├── logs/                              # Structured JSON logs
├── docs/
│   ├── architecture.md
│   └── client-states/                 # Per-client status files
├── graphify-out/                      # Graphify code graph (generated by /graphify ., gitignored)
├── docker-compose.yml
├── requirements.txt
├── .env.example                       # Template, never real values
└── .gitignore
```

## Rules
- `config/` holds ALL business rules — never hardcode in `src/` or `prompts/`
- `prompts/` is versioned with symlink to `current`
- `tests/fixtures/` contains real anonymized data, not invented data
- `.env.example` documents required vars without real values
- `logs/` uses structured JSON, not plain text
- The authored memory vault is **NOT in the repo** — it lives centrally at `~/SecondBrain/projects/<slug>/` so it survives across sessions and cwds. Never scaffold a repo-local `memory/`; see `knowledge-layer.md`
- `.claude/commands/next.md` and `verify.md` are always present (every category) — the companion loop and the verification barrier; see `companion.md` and `graph-verification.md`
- `graphify-out/` is generated with `/graphify .` and gitignored — never committed, regenerated on a fresh clone
- git worktrees live OUTSIDE the repo (`../<repo>-wt/<slug>`), never nested inside the tracked tree; `*-wt/` and `.worktrees/` are gitignored (see `parallelization.md`)
